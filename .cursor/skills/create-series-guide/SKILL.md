# シリーズガイド作成スキル

1問ずつ質問してシリーズガイドの叩き台を作り、人間が確認してからAPIで保存する。
叩き台はあくまで素材。最終判断は必ず人間が行う。

---

## 前提確認

`GET http://localhost:3000/api/data` を実行する。

- 接続失敗 → `pnpm dev` の起動を促して停止する。
- 既存のガイド内容がある → 内容を表示して「上書きしてよいか」を確認してから進む。

---

## 質問ステップ（1問ずつ進める）

回答が薄い・曖昧な場合は「もう少し具体的に教えてください」と深掘りしてから次へ進む。

| # | 質問 | フィールド |
|---|------|----------|
| Q1 | 「このシリーズを終えた受講者が、接客の場面でどんな行動ができるようになってほしいですか？また、実際の接客経験とどう組み合わせるイメージですか？（ドリルだけでは補えない部分も含めて）」 | `purpose` |
| Q2 | 「このシリーズで必ず登場させたいキーワードや概念を挙げてください（複数可）」 | `terms` |
| Q3 | 「このシリーズに、Claude に積極的に使わせたい中心的な分類概念・補助語はありますか？（例：格とTPOなら「段」、帯なら「帯の格」など。ない場合は空欄でOK）」 | `aux_concept` |
| Q4 | 「使ってはいけない言葉・表現はありますか？（フォーマル度・ドレスコード・ランク・レベルはすでに禁止済みです。追加があれば）」 | `forbidden_synonyms` |
| Q5 | 「特殊ケースや例外として受講者に伝えたい知識はありますか？（お客様から聞かれて詰まりやすい場面や、単純な分類では収まらないグレーゾーンがあれば）」 | `exceptions` |
| Q6 | 「問題文はどんな言葉づかい・トーンで書いてほしいですか？（例：お客様が目の前にいる場面設定で書く・ですます調・短文）」 | `writing_style` |
| Q7 | 「このシリーズの問題を解くとき、受講者はどんなお客様・どんな状況を想定してほしいですか？典型的な場面を1つ具体的に描写してください」 | `purpose` + `writing_style` に反映 |

---

## 叩き台の出力と確認

全質問の回答をもとに以下の形式で出力する。

```
【シリーズガイド 叩き台】

■ 習得目標
{purpose}

■ 主要語句
{terms}

■ 補助概念（任意）
{aux_concept}

■ 禁止同義語
{forbidden_synonyms}（フォーマル度・ドレスコード・ランク・レベルを含む）

■ 例外・注意事項
{exceptions}

■ 文体・トーン
{writing_style}
```

出力後に確認する：
「このまま保存しますか？修正したい箇所があれば教えてください。」

修正があれば該当箇所を直して再表示 → 再度確認する（合格まで繰り返す）。

---

## 保存

「保存する」と承認を得たら API を呼ぶ。

```
POST http://localhost:3000/api/save-guide
Content-Type: application/json

{
  "type": "series",
  "guide": {
    "purpose":            "...",
    "terms":              "...",
    "aux_concept":        "（なければ空文字）",
    "forbidden_synonyms": "フォーマル度・ドレスコード・ランク・レベル（追加分があればここに）",
    "exceptions":         "...",
    "writing_style":      "..."
  }
}
```

保存完了後：
「シリーズガイドを保存しました。次は `create-course-guide` スキルでコースガイドを作成できます。」
