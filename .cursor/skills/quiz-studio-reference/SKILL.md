# Quiz Studio 参照スキル

## このスキルの位置づけ

`Graduation-work`（呉服Quiz工房）が段階的に近づいていく「完成形」の仕様書。
実装・設計・改善の意思決定に使う。一足飛びに模倣しない——現在地を確認しながら、
次の一手を考えるための羅針盤。

---

## Quiz Studio とは

AI-Driven School 運営（Surprise社）が社内で使うローカルの問題制作ツール。
本気AIドリル（学習者向けドリルサービス）の問題を作るために開発された。

| 項目 | 内容 |
|------|------|
| 起動 | `pnpm dev`（ローカル。サーバー公開なし） |
| 技術スタック | Next.js + shadcn/ui + Tailwind CSS + Anthropic Agent SDK |
| 規模 | 1シリーズ 600〜700問。1〜2週間で1シリーズ完成 |
| 使用者 | 運営チームのみ（複数人で各自のPCで使用） |

## UI 構成（4 要素）

### 左パネル — CONTENT

```
■ Git完全マスターシリーズ  公開  8コース
■ Web開発基礎シリーズ     公開  4コース
▼ Web開発実践シリーズ     公開  8コース
   □ シリーズガイド
   □ シリーズテスト
   ▼ ビルドとモダンCSS     ○○○○  8レッスン
   ▼ React・コンポーネント編 ○○○○  8レッスン
   ...
```

- シリーズ一覧（カラーアイコン・公開/下書きバッジ・Nコース数）
- シリーズを展開 → シリーズガイド / シリーズテスト / コース一覧
- コースを展開 → レッスン一覧（Nレッスン数・状態ドット）
- 下部に「追加」ボタン群（シリーズ・コース・レッスン追加）

### 上部タブバー

ブラウザタブ風にコース/シリーズを複数同時に開ける。

### 中央パネル — メインコンテンツ

| 表示要素 | 説明 |
|----------|------|
| コースガイドテキスト | ガイドの文章が先頭に表示 |
| 品質バナー | 「✓ 完了 — すべての品質基準をクリアしています」 |
| 問題カード | 難度・問題番号・PASSED/FAILEDバッジ・承認ボタン |
| 問題内ビジュアル | 図解・ファイル一覧・UIスクリーンショット等の挿絵 |
| アクションボタン | 「再レビュー」「テスト実行」 |

シリーズガイド生成後は中央に生成結果が表示され、「✓ 承認 / × 要修正」で判断する。

### 右パネル — Agents Bar

3タブ構成：

**フリーチャット（スキルセレクター）**

```
コース対象
  ⚡ コースレビュー
  ⚡ コース分析
  ⚡ コース作成
  ⚡ コースリセット

シリーズ対象
  ⚡ シリーズ分析
  ⚡ シリーズレビュー
  ⚡ シリーズ作成
```

- スキルを選択 → 初期メッセージ（任意）を入力 → 「＋ セッションを開始」
- 生成結果が中央パネルに出力される
- 過去セッションはアーカイブで参照可能

**品質レビュー / クイズ作成**（別タブ）

## コンテンツ階層

```
N シリーズ
└─ シリーズガイド（設計思想・対象者・メタファー等）
└─ シリーズテスト
└─ N コース
   └─ コースガイド
   └─ N レッスン（8〜12問）
      └─ 各問題（四択 or ○×）
         ├─ 問題文
         ├─ 選択肢（四択のみ）
         ├─ 正解
         ├─ 解説
         └─ ビジュアル挿絵（任意）
```

## 問題作成フロー（レッスン1本）

```
1. シリーズガイド作成
   grill-me → 「シリーズ作成」スキル起動 → 生成 → 承認/修正

2. コースガイド作成
   シリーズガイドを元に「コース作成」スキル起動 → 生成 → 承認/修正

3. レッスン（下書き）生成
   シリーズガイド + コースガイド + 承認済み前レッスン を渡してAIが生成

4. 機械チェック
   禁止語・問題数・フォーマット・文字数 などをプログラムで検査

5. AIサブエージェントレビュー（並列・問題単位）
   品質チェックシート（Markdown）に照らして1問1エージェントで評価
   NG項目ごとに理由を出力（「やったふり」防止）

6. 批判的ユーザー視点レビュー
   別サブエージェントが「批判的なユーザー」として問題を解き、フィードバック

7. 修正 → 更新した問題のみ再レビュー（4〜6 を繰り返す）

8. 全問合格 → 承認（これでよい）
```

**スキップ防止**：AIがプロセスを自己判断でスキップしないよう、各ステージの区切りにフックを仕掛けている。

## コンテンツ設計哲学

| 原則 | 内容 |
|------|------|
| 同一メタファー | 1概念 = 1比喩表現のみ。「Gitのコミット = セーブポイント」なら他の表現は不可 |
| 復習の自然な組み込み | 復習レッスンは作らない。過去の概念が次のレッスンで自然に再登場する設計 |
| 復習頻度の計測 | 1概念が何回・いつ再登場するかを数字で管理 |
| 上流は人間が書く | シリーズガイド・コースガイドは叩き台をAIが作っても、詰め切るのは人間 |

## 機械チェック項目（本家の実装から推定）

- 禁止語の含有チェック
- 問題数（8〜12問の範囲内か）
- 問題文の文字数（長すぎ・短すぎ）
- 四択/○× フォーマットの正確性
- 解説の有無・文字数
- （呉服Quiz工房での追加）禁止同義語：フォーマル度・ドレスコード・ランク・レベル

## 現在の Graduation-work との差分

| 項目 | Graduation-work（現在） | Quiz Studio（目標） |
|------|------------------------|---------------------|
| シリーズ数 | 1（ハードコード） | N（DB管理） |
| DB | JSON ファイル | SQLite + Drizzle ORM（移行予定） |
| AI実装 | 直接 Claude API 呼び出し | Anthropic Agent SDK |
| サブエージェントレビュー | なし | あり（並列・問題単位） |
| Agents Bar | なし（後回し） | 右パネルに実装 |
| 問題数/レッスン | 8問固定 | 8〜12問 |
| UIフレームワーク | Tailwind のみ | shadcn/ui + Tailwind |
| ビジュアル挿絵 | なし | 問題内に図解 |
| スキルの場所 | なし | 右パネルから呼び出し |
| シリーズテスト | なし | あり |

## 呉服 Quiz 工房の現在地

- 技術スタック: Next.js 16 + Tailwind CSS 4
- データ: `data/kakuto-tpo/` JSON（series, course, lessons）
- 対象シリーズ: 格とTPO（1シリーズ・1コース・3レッスン）
- 状態: 実装済み・動作確認済み
- 次のマイルストーン: SQLite + Drizzle ORM への DB 移行
