# レッスン問題作成スキル

呉服Quiz工房（`http://localhost:3000`）でレッスン1本を仕上げる6ステップ。
アプリが起動済みであることを前提とする。

---

## STEP 0：起動・状態確認

`GET http://localhost:3000/api/data` を実行してデータを取得する。

- **接続失敗**: ユーザーに `pnpm dev` の起動を促して停止する。
- **接続成功**: レスポンスの `lessons` 配列を確認する。
  - `status: "pending"` のレッスンのうち `lessonIndex` が最小のものを対象に選ぶ。
  - その1つ前のレッスン（`lessonIndex - 1`）が `status: "approved"` であることを確認する（生成ロック解除条件）。レッスン1の場合はこのチェックをスキップ。

---

## STEP 1：シリーズ・コースガイドの確認

`GET /api/data` のレスポンスから以下を確認する。

**シリーズガイド**（`series.guide`）の必須フィールド:

| フィールド | 内容 |
|-----------|------|
| `target` | 対象者（誰に向けたドリルか） |
| `purpose` | 目的（何を習得させるか） |
| `terms` | 主要語句 |
| `dan_definition` | 格の定義 |
| `forbidden_synonyms` | 禁止同義語（フォーマル度など） |

**コースガイド**（`course.guide`）の必須フィールド:

| フィールド | 内容 |
|-----------|------|
| `lesson_roles` | 各レッスンの役割・位置づけ |
| `must_include` | 必ず含む概念 |
| `exclude` | 除外する内容 |

どれかが空文字ならユーザーにアプリUI（P2ガイド編集）で記入を促して停止する。

---

## STEP 2：レッスン生成

生成には Anthropic API キーが必要。**アプリUI経由でのみ実行**できる。

ユーザーへの案内:
1. `http://localhost:3000` でアプリを開く
2. ⚙ アイコンで API キーを貼り付ける（ページを閉じると消える）
3. P1 ツリーで対象レッスンを選択する
4. 「このレッスンを生成」ボタンを押す

生成完了後（UIに設問が表示されたら）、ユーザーに知らせてもらうかページ再読み込みを待つ。
再度 `GET /api/data` を取得して `lessons[対象].status === "draft"` を確認してから次へ進む。

---

## STEP 3：機械チェック確認

`GET /api/data` のレッスンデータに `inspection` フィールドが含まれる。

- `inspection.status === "pass"` → STEP 4 へ進む
- `inspection.status === "fail"` → `inspection.errors` をユーザーに報告し STEP 5 へ

**機械チェック項目（参考）**:

| 項目 | ルール |
|------|--------|
| 設問数 | 8問 |
| 四択 | 選択肢 4つ・正解インデックス 0〜3 |
| ○× | `answer` が `true` か `false` |
| 解説 | 全設問に必須 |
| 禁止語 | フォーマル度・ドレスコード・ランク・レベル |

---

## STEP 4：AI 品質レビュー

機械チェックに合格した設問を内容の観点でレビューする。
`series.guide` と `course.guide` の内容を参照しながら、各設問を以下の観点で評価する。

### 評価観点

| 観点 | 基準 |
|------|------|
| **出題範囲** | このレッスンのテーマ（`lesson.title`）に沿った内容か |
| **内容の正確性** | 正解・解説が呉服の知識として正しいか |
| **選択肢の品質**（四択のみ） | ダミー選択肢が「もっともらしいが明確に誤り」か |
| **解説の質** | 「なぜその答えが正しいか」の理由を説明しているか |
| **重複** | 同レッスン内の他の設問と実質的に同じ問いを扱っていないか |
| **難易度バランス** | 8問全体で易・中・難が偏りなく混在しているか |
| **接客場面の再現性** | 8問のうち少なくとも一部が、お客様との実際の場面を想起させるか。土台知識を問う問題が混在することは問題ない |

### レポート形式

設問ごとに出力する:

```
Q{N}（{four_choice|true_false}）: PASS / FAIL
  FAIL理由: {理由}  ← FAIL の場合のみ
  修正案:   {問題文・選択肢・正解・解説の具体的な修正内容}  ← FAIL の場合のみ
```

最後にサマリー:

```
---
合格: {N}問 / 8問  要修正: {N}問
```

全問 PASS の場合は STEP 6 へ進む。

---

## STEP 5：修正

STEP 3 または STEP 4 で不合格の設問を修正する。

1. 各不合格設問の修正案をユーザーに提示し、承認を得る（承認 / 差し戻し / 別案を提示）
2. 承認された修正を API で保存する:

```
POST http://localhost:3000/api/save-lesson
Content-Type: application/json

{
  "lessonId": "<id>",
  "questions": [<全8問の配列。修正した設問を含む>]
}
```

保存後、API レスポンスに含まれる最新の `inspection` を確認し、STEP 4 からやり直す。
全問 PASS になるまで STEP 4 → STEP 5 を繰り返す。

---

## STEP 6：承認

全問合格（機械 PASS + AI PASS）を確認後、承認 API を呼ぶ:

```
POST http://localhost:3000/api/approve-lesson
Content-Type: application/json

{ "lessonId": "<id>" }
```

承認完了後、次の `status: "pending"` レッスンが残っていれば STEP 0 に戻る。

---

## Agents Bar 移植メモ

このフローを将来アプリ内 Agents Bar に移植する際の対応関係:

| スキルの STEP | Agents Bar 対応 |
|-------------|----------------|
| STEP 0 | セッション開始時の自動状態チェック |
| STEP 1 | ガイド入力のバリデーション |
| STEP 2 | 「このレッスンを生成」ボタン（既存） |
| STEP 3 | 機械検査（生成直後に自動実行・既存） |
| STEP 4 | AI サブエージェント（設問ごとに並列実行） |
| STEP 5 | インライン設問編集 + 再検査 |
| STEP 6 | 「これでよい」ボタン（既存） |
