# レッスン問題作成スキル

呉服Quiz工房（`http://localhost:3000`）でレッスン1本を仕上げる6ステップ。
アプリが起動済みであることを前提とする。

---

## STEP 0：起動・状態確認

`GET http://localhost:3000/api/data` を実行してデータを取得する。

- **接続失敗**: ユーザーに `pnpm dev` の起動を促して停止する。
- **接続成功**: レスポンスの `courses[].lessons` を確認する。
  - 対象コースを確認したうえで、そのコース内で `status: "pending"` かつ `lessonIndex` が最小のレッスンを選ぶ。
  - 同じコースの1つ前のレッスン（`lessonIndex - 1`）が `status: "approved"` であることを確認する（生成ロック解除条件）。コース内レッスン1の場合はこのチェックをスキップ。

---

## STEP 1：シリーズ・コースガイドの確認

`GET /api/data` のレスポンスから以下を確認する。

**シリーズガイド**（`series.guide`）の必須フィールド:

| フィールド | 内容 |
|-----------|------|
| `purpose` | 目的（何を習得させるか） |
| `terms` | 主要語句 |
| `aux_concept` | 補助概念（このシリーズの中心的な分類概念・補助語とその定義。任意・空欄可） |
| `forbidden_synonyms` | 禁止同義語（フォーマル度など） |

**コースガイド**（対象コースの `guide`）の必須フィールド:

| フィールド | 内容 |
|-----------|------|
| `lesson_roles` | 各レッスンの役割・位置づけ |
| `must_include` | 必ず含む概念 |
| `exclude` | 除外する内容 |

どれかが空文字ならユーザーにアプリUI（P2ガイド編集）で記入を促して停止する。

---

## 参照テキスト（共通）

ガイド確認のあと、レビュー・修正の前に `data/references/` を読む。アプリ生成（`lib/prompt.ts`）も同じフォルダから該当ファイルを初稿に載せる。

1. `data/references/README.md` を読み、ファイル一覧と対応レッスンを把握する。
2. 対象レッスンのテーマ（`lesson.title`）に関連するファイルがあれば読み込む。
3. **ガイドが正。** 参照は事実（柄の位置、袖の長さ、既婚・未婚、代表品目）の照合に使う。レンズ・出題範囲・禁止語はガイドに従う。参照の言い回し（フォーマル度、段の序列、相当する洋装、題材の置き場）を設問に写さない。
4. 該当ファイルがなければスキップする。

`kakuzuke-youfuku-hikaku.txt` は洋服対応であり、生成には載せない。レビューで「相当する洋装」型が出ていないかの確認にだけ使う。

---

## STEP 2：レッスン生成

生成には Anthropic API キーが必要。**アプリUI経由でのみ実行**できる。初稿には `lib/prompt.ts` が該当する参照テキストを載せる。エージェントは上の共通手順で同じ参照を把握しておく。

ユーザーへの案内:
1. `http://localhost:3000` でアプリを開く
2. ⚙ アイコンで API キーを貼り付ける（ページを閉じると消える）
3. P1 ツリーで対象レッスンを選択する
4. 「このレッスンを生成」ボタンを押す

生成完了後（UIに設問が表示されたら）、ユーザーに知らせてもらうかページ再読み込みを待つ。
再度 `GET /api/data` を取得して、対象レッスンの `status === "draft"` を確認してから次へ進む。

---

## STEP 3：機械チェック確認

`GET /api/data` のレッスンデータに `inspection` フィールドが含まれる。

- `inspection.status === "pass"` → STEP 4 へ進む
- `inspection.status === "fail"` → `inspection.errors` をユーザーに報告し STEP 5 へ

**機械チェック項目（参考）**:

| 項目 | ルール |
|------|--------|
| 設問数 | 8問 |
| 四択 | 選択肢 4つ・正解インデックス 0〜3。正解だけが他より8文字以上長いと不合格 |
| ○× | `answer` が `true` か `false` |
| 解説 | 全設問に必須 |
| 禁止語 | フォーマル度・ドレスコード・ランク・レベル |

---

## STEP 4：AI 品質レビュー

機械チェックに合格した設問を内容の観点でレビューする。

参照は「参照テキスト（共通）」に従う。内容の正確性では、参照の事実と矛盾する正解・解説を FAIL とする。ガイドと参照が矛盾したらガイドが正。参照にない情報は出典を疑い要確認とする。

### レビュー実施

`series.guide` と対象コースの `guide` の内容を参照しながら、各設問を以下の観点で評価する。

### 評価観点

| 観点 | 基準 |
|------|------|
| **出題範囲** | このレッスンのテーマ（`lesson.title`）に沿った内容か |
| **内容の正確性** | 正解・解説が呉服の知識として正しいか |
| **問いと正解の軸** | 聞いていること（何で決まるか／何のためか／いつか）と正解が同じ軸か。定義で答えているのに要因を聞いている、などは FAIL |
| **答え漏らし** | 問題文が正解の手がかりを先に置いていないか。続柄を書いて「関係を聞け」と問う、規模を書いて「場を聞け」と問う、などは FAIL |
| **学習者視点** | 設問は学習者（売り場の販売員）が身につける知識・判断を問う。ドリルの設計を問うのは FAIL。判定と直し方は下の「ドリル設計メタ問い」を使う |
| **導入順序** | このレッスンより後で出す補助語・メタファーを、問題文・選択肢・解説に出していないか（例：レッスン1に規定演技／自由演技） |
| **語の限定** | `writing_style` どおりか。コース1は「品目の格」「TPOの格」。裸の「格」だけで問わない。「選択品」「アイテム」は使わない |
| **選択肢の品質**（四択のみ） | ダミーが「もっともらしいが明確に誤り」か。4択は同じ構文・同程度の長さ。正解にだけ理由や条件を足して長くしない（長さで当たる）。理由は解説に書く |
| **解説の質** | 「なぜその答えが正しいか」の理由を説明しているか。未導入の語で説明していないか |
| **重複** | 同レッスン内の他の設問と実質的に同じ問いを扱っていないか。同じ固有シナリオ（「姪の結婚式」など）をコース内で繰り返して答えを固定していないか |
| **難易度バランス** | 8問全体で易・中・難が偏りなく混在しているか |
| **接客場面の再現性** | 8問のうち少なくとも一部が、お客様との実際の場面を想起させるか。土台知識を問う問題が混在することは問題ない |

### ドリル設計メタ問い（再発防止）

ガイドの `lesson_roles` / `must_include` / `revisit` / `exclude` は、**出題者が範囲を決めるためのメモ**である。そのメモ自体を学習者に問うな。

**判定**: 問題文・選択肢から「このシリーズ／このコース／このレッスン／この地図」と、配置の語（どう扱う・どう位置づける・押さえる範囲・再登場・題材）を外す。売り場の知識として成立しなければ FAIL。成立しても、正解やダミーが「カリキュラム上の置き場」なら FAIL。

**赤旗**（問題文・選択肢。解説は次項）:

- このシリーズ／このコース／このレッスン／この地図／このドリル
- どう扱うか／どう位置づけるか（著者の配置）
- 押さえる範囲／再登場／題材として
- 唯一の補助語／唯一のメタファー（設計宣言として聞くとき）

**解説は例外**: 「具体的な運用は後のコース」は先送りの注記として可。問題文・選択肢でそれを正解やダミーにしない。

**導入順序との違い**: 導入順序は、まだ出していない語を出さないこと。本観点は、語が出ていても「このドリルではこう置く」を問わないこと。

**誤った直し方**: 「このコースではどう扱うか」を「どう位置づけるか」に言い換えるだけでは FAIL のまま。学習者の知識に言い換える。

**FAIL の型と直し方**:

| 型 | 悪い例 | 直し |
|---|---|---|
| 設計のレンズ選定 | 「このシリーズで装いを考えるときの、唯一の補助語はどれか。」 | 「装いを見るとき、先に置く見方はどれか。」正解は規定演技と自由演技 |
| コースへの配置 | 「五つ紋の色留袖は、規定演技としてどう位置づけるか。」ダミーに「紋の数で格を動かす題材」 | 「五つ紋の色留袖は、どの装いの代表か。」ダミーは品目の誤り（自由／あいだ／洒落もの）。後のコースの題材かは聞かない |
| レッスンの立場 | 「このレッスンの立場として正しいものはどれか。」 | 決まりそのものの理由を問う。「決まりは、場に集う人への敬意を装いで揃える型である。」 |
| 地図の範囲 | 「紋や帯・小物を、この地図コースで押さえる範囲はどれか。」 | 今の判断に要る範囲を、売り場の言葉で問う。「今日の見立てで、紋や帯・小物まで手順を決めるか。」 |

「この場はどちら寄りか」「この要望はどちら寄りか」の「この」はお客様の場・要望であり、赤旗ではない。

### レポート形式

設問ごとに出力する:

```
Q{N}（{four_choice|true_false}）: PASS / FAIL
  FAIL理由: {理由}  ← FAIL の場合のみ
  修正案:   {問題文・選択肢・正解・解説の具体的な修正内容}  ← FAIL の場合のみ
```

最後にサマリー:

```
---
合格: {N}問 / 8問  要修正: {N}問
```

全問 PASS の場合は STEP 6 へ進む。

---

## STEP 5：修正

STEP 3 または STEP 4 で不合格の設問を修正する。

1. 各不合格設問の修正案をユーザーに提示し、承認を得る（承認 / 差し戻し / 別案を提示）
2. ドリル設計メタ問いを直すときは、設計語の言い換えで済ませず、学習者の知識・判断に変換する
3. 参照の事実と矛盾する正解・解説は直す。ガイドと参照が矛盾したらガイドに合わせる
4. 承認された修正を API で保存する:

```
POST http://localhost:3000/api/save-lesson
Content-Type: application/json

{
  "lessonId": "<id>",
  "questions": [<全8問の配列。修正した設問を含む>]
}
```

保存後、API レスポンスに含まれる最新の `inspection` を確認し、STEP 4 からやり直す。
全問 PASS になるまで STEP 4 → STEP 5 を繰り返す。

---

## STEP 6：承認

全問合格（機械 PASS + AI PASS）を確認後、承認 API を呼ぶ:

```
POST http://localhost:3000/api/approve-lesson
Content-Type: application/json

{ "lessonId": "<id>" }
```

承認完了後、次の `status: "pending"` レッスンが残っていれば STEP 0 に戻る。

---

## Agents Bar 移植メモ

このフローを将来アプリ内 Agents Bar に移植する際の対応関係:

| スキルの STEP | Agents Bar 対応 |
|-------------|----------------|
| STEP 0 | セッション開始時の自動状態チェック |
| STEP 1 | ガイド入力のバリデーション |
| STEP 2 | 「このレッスンを生成」ボタン（既存） |
| STEP 3 | 機械検査（生成直後に自動実行・既存） |
| STEP 4 | AI サブエージェント（設問ごとに並列実行） |
| STEP 5 | インライン設問編集 + 再検査 |
| STEP 6 | 「これでよい」ボタン（既存） |
