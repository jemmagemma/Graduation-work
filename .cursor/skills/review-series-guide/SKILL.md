# シリーズガイド レビュー

API から現在のシリーズガイドを取得し、観点ごとに評価してから保存する。

固定認識: [../create-lesson-questions/locked-principles.md](../create-lesson-questions/locked-principles.md)

---

## 前提確認

`GET http://localhost:3000/api/data` を実行する。

- 接続失敗 → `pnpm dev` を促して停止する
- `series.guide` が空 → `create-series-guide` を促して停止する

Windows では `curl` ではなく `node` の `fetch` を使う。

---

## レビュー評価

| 観点 | 基準 |
|------|------|
| **具体性** | 目的・補助概念が同じ解釈になるか。規定演技／自由演技は例えであり、名称暗記を要求していないか |
| **整合性** | フィールド同士が矛盾していないか。所有の変化をレッスンの仕事（標語）にしていないか。問数はコースで宣言すると読めるか |
| **禁止語の網羅** | 問題文で使われそうな言い換えを列挙しているか |
| **スコープ明確性** | 扱う／扱わないが明示されているか。ファッション延長、相当する洋装、ドリル設計メタ問いを外しているか |
| **文体の指定** | 制作者が迷わないか。舞台は売場。別人格で通じる文面を求めているか |
| **例外の網羅** | グレーゾーンと、昔の前提／今の場のずれをカバーしているか。正しい伺いと、決めつけになる伺いが分かれているか |

### レポート形式

```
【シリーズガイド レビュー結果】

{観点名}: PASS / FAIL
  FAIL理由: {理由}
  改善案:   {具体的な改善文案}

---
合格: {N}項目 / 6項目  要改善: {N}項目
```

---

## 改善の確認と保存

FAIL があれば「{観点名} の改善案を採用しますか？」
承認された改善を反映し、「このまま保存しますか？」
「保存する」のあと API を呼ぶ。API は DB だけを更新する。同じ内容を JSON にも書く。

```
POST http://localhost:3000/api/save-guide
{ "type": "series", "guide": { <改善済みの全フィールド> } }
```

保存後: 「シリーズガイドを更新しました。」
