# コースガイド レビュースキル

APIから現在のコースガイドとシリーズガイドを取得し、照合しながら観点ごとに評価・改善案を提示してから保存する。

---

## 前提確認

`GET http://localhost:3000/api/data` を実行する。

- 接続失敗 → `pnpm dev` の起動を促して停止する。
- `series.guide` が空 → 先に `create-series-guide` を実行するよう促して停止する。
- `course.guide` が空 → 先に `create-course-guide` を実行するよう促して停止する。

---

## レビュー評価

シリーズガイドの内容と照合しながら、コースガイドを以下の観点で評価する。

| 観点 | 基準 |
|------|------|
| **シリーズ整合性** | コースの内容がシリーズガイドの目的・対象者・主要語句と一致しているか |
| **レッスン分割の妥当性** | 各レッスンの役割が明確に分かれていて重複・抜け漏れがないか |
| **必須内容の具体性** | `must_include` が「これを見ればレッスン制作者が迷わない」レベルで具体的か |
| **復習設計** | 前レッスンの概念が後レッスンに再登場する設計が意図的に組まれているか |
| **除外の明示** | 扱わない内容が明示されていて、制作者が誤って含めないようになっているか |
| **修了目標の明確さ** | 修了後の姿が「測定・確認できる」レベルで具体的か |

### レポート形式

```
【コースガイド レビュー結果】

{観点名}: PASS / FAIL
  FAIL理由: {理由}  ← FAIL の場合のみ
  改善案:   {具体的な改善文案}  ← FAIL の場合のみ

---
合格: {N}項目 / 6項目  要改善: {N}項目
```

---

## 改善の確認と保存

FAIL 項目がある場合：
「{観点名} の改善案を採用しますか？修正したい場合は別案を教えてください。」

承認された改善をガイドに反映し、確認用に全体を再表示する：
「このまま保存しますか？」

「保存する」と承認を得たら API を呼ぶ。

```
POST http://localhost:3000/api/save-guide
Content-Type: application/json

{ "type": "course", "guide": { <改善済みの全フィールド> } }
```

保存完了後：
「コースガイドを更新しました。次は `create-lesson-questions` スキルでレッスン問題を作成できます。」
