# コースガイド レビュー

API から現在のコースガイドとシリーズガイドを取得し、照合してから保存する。

固定認識: [../create-lesson-questions/locked-principles.md](../create-lesson-questions/locked-principles.md)

---

## 前提確認

`GET http://localhost:3000/api/data` を実行する。

- 接続失敗 → `pnpm dev` を促して停止する
- `series.guide` が空 → `create-series-guide` を促して停止する
- 対象コースの `guide` が空 → `create-course-guide` を促して停止する
- 対象コースを確認してから進む

Windows では `curl` ではなく `node` の `fetch` を使う。

---

## レビュー評価

| 観点 | 基準 |
|------|------|
| **シリーズ整合性** | 目的・対象者・主要語句と一致しているか。シリーズの古い一文より、このコースの役割が具体か |
| **レッスン分割の妥当性** | 各回の役割が分かれているか。標語化していないか（地図レッスン3は所有の標語ではなく前提合わせ） |
| **必須内容の具体性** | `must_include` が制作者を迷わせないか |
| **復習設計** | 前の概念が後に再登場する意図があるか |
| **除外の明示** | 扱わない内容が明示されているか（ファッション延長、相当する洋装、ドリル設計メタ問い） |
| **修了目標の明確さ** | 修了後の姿が測定できるか |
| **問数設計** | `question_counts` が全レッスン分あり、役割の厚みと一致しているか。8問固定で薄い回を水増ししていないか。コース2〜5の `[8, 8, 8]` は仮置きなら、未グリルと注記する |

### レポート形式

```
【コースガイド レビュー結果】

{観点名}: PASS / FAIL
  FAIL理由: {理由}
  改善案:   {具体的な改善文案}

---
合格: {N}項目 / 7項目  要改善: {N}項目
```

---

## 改善の確認と保存

FAIL があれば「{観点名} の改善案を採用しますか？」
承認された改善を反映し、「このまま保存しますか？」
「保存する」のあと API を呼ぶ。`question_counts` を落とさない。API は DB だけを更新する。同じ内容を JSON にも書く。

```
POST http://localhost:3000/api/save-guide
{ "type": "course", "courseId": "<対象コースのid>", "guide": { <改善済みの全フィールド> } }
```

保存後: 「コースガイドを更新しました。次は `create-lesson-questions` でレッスン問題を作成できます。」
